# 動作確認の状況

[← README に戻る](../README.md)

実際にテストして「接続して遊べる」ことを確認した組み合わせです（v1.2 系）。
確認していない組み合わせが動かない、という意味ではありません。

## NAT タイプ × NAT タイプ

| ホスト → ジョイン | Cone NAT | Symmetric NAT |
|------------------|----------|---------------|
| **Cone NAT** | ✅ 直接接続（QUIC。数秒で成立） | ✅ Relay 経由（15 秒前後） |
| **Symmetric NAT** | ✅ Relay 経由（15 秒前後） | 未測定 |

NAT タイプはアプリの **Diag** タブで確認できます
（「Cone NAT (P2P ready)」または「Symmetric NAT (relay mode)」）。

Relay の「15 秒前後」は、直接接続（QUIC）を 8 秒待ってから切り替えるためです。
STUN が使えない環境（UDP 遮断など）では、この待ち時間なしに最初から Relay に進みます。

## OS の組み合わせ（NAT が条件を満たしている場合）

| ホスト | ジョイン | 結果 |
|-------|---------|------|
| macOS | macOS | ✅ |
| macOS | Windows | ✅ |
| macOS | Linux | ✅ |
| Linux | macOS | ✅ |
| Linux（Paper サーバー） | macOS | ✅ |

x86_64 と aarch64 の混在も問題ありません。

## Minecraft

| 種別 | 動作 |
|------|------|
| 通常の Minecraft Java Edition（LAN に公開） | ✅ |
| Paper / Spigot / Vanilla サーバー | ✅（MineScale は TCP をそのまま中継します） |
| 公式アカウント | ✅ |
| ジョイン側が有効なアカウント | ✅ 一覧・直接アドレスのどちらでも |
| ジョイン側が無効なセッション（オフラインアカウントなど） | ⚠️ **LAN の一覧から入れば ✅**。**直接アドレスだと「無効なセッション」で ❌** |
| ホスト側がオフラインアカウント | ✅ 確認されるのは入ってくる側なので、問題ない |
| Paper などの専用サーバー | ✅ ただし既定（`online-mode=true`）では、一覧・直接を問わず有効なログインが必要 |

## 長時間のセッション

- Relay 経由で **3 時間以上**の連続プレイを確認
- 共有 URL の期限（15 分）が切れても、すでに繋がっている接続は影響を受けない
- 仲介サーバーのメモリ使用量・ファイル記述子数は、長時間でも増え続けない

## 回線の種類ごとの傾向

同梱の [`nat-scanner`](../nat-scanner/README.md) で、いろいろな回線の NAT の挙動を測りました
（外部ポートが接続先ごとに変わるか＝直接接続に向くか）。

| 回線 | 結果 |
|------|------|
| 家庭の光回線 | Cone（直接接続に向く） |
| 集合住宅の共用ルーター配下 | Cone |
| 携帯キャリアのテザリング（複数社） | Cone |
| バスや駅の公衆 Wi-Fi | Cone（多くは携帯回線が出口） |
| VPS | NAT なし（グローバルアドレス直結） |
| **企業ネットワーク** | **Symmetric（測定した 1 件）** |

Symmetric は、測定した範囲では企業ネットワークに限られました。そのため大半の環境では
直接接続（QUIC）で繋がり、Symmetric のときだけ Relay に切り替わります。
