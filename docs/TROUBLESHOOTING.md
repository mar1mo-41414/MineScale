## Windows でダウンロードや起動がブロックされる

ダウンロード時に **「一般的にダウンロードされていません」**、起動時に
**「Windows によって PC が保護されました」** という警告が出ることがあります。

これは Windows の SmartScreen が「ダウンロード数の少ない exe」を自動的に警告するためで、
**ファイルに問題があるわけではありません**（まだ利用実績が少ないだけです）。

### 一番かんたん: winget で入れる

```powershell
winget install minescale
```

winget 経由なら、この警告は出ません。

### ダウンロード時にブロックされたら

1. ブラウザの「ダウンロード」一覧で、該当ファイルの **「…」(三点)** メニューを開く
2. **「保持する」**（英語版は **"Keep"**）を選ぶ
3. 確認ダイアログで **「危険なファイルを保持する」** / **"Keep anyway"** を選ぶ

### 起動時にブロックされたら

「Windows によって PC が保護されました」の画面で:

1. 画面下の小さな **「詳細情報」** をクリック
2. 出てきた **「実行」** を押す

### PowerShell から直接ダウンロードする

```powershell
Invoke-WebRequest `
  -Uri "https://github.com/mar1mo-41414/MineScale/releases/latest/download/mc-share-gui-windows-x64.exe" `
  -OutFile "mc-share-gui.exe"
```

## マイクラのマルチプレイ画面にワールドが出てこない

**症状**: ジョインの「Connect」を押して接続できたのに、マイクラの「マルチプレイ」画面に
ワールドが現れない（特に Mac で、環境により起こり得ます）。

### 対処法: 直接アドレスを入力する

接続後、アプリに **`127.0.0.1:XXXXX`** というアドレスが表示されます（CLI でも同じです）。

1. マイクラを開く → **「マルチプレイ」**
2. 画面下の **「サーバーを追加」**（または「直接接続」）を選ぶ
3. サーバーアドレスに **`127.0.0.1:XXXXX`** を入力する（`XXXXX` は表示された番号）
4. 「完了」→ 接続

この方法は LAN 自動検出を使わないので、確実です。ただし、**ジョイン側のログインが有効である必要があります**
（オフラインアカウントだと「無効なセッション」で弾かれます。詳しくは下の項目）。

### 追加のチェック

- **VPN を切ってみる**（仮想ネットワークがあると LAN 検出が乱れることがあります）
- **マイクラを、MineScale の接続が済んでから開く**
- **macOS のファイアウォール**で Minecraft / Java をブロックしていないか確認する
- **同じ Wi-Fi にいる必要はありません**（P2P / リレーで繋がるため）
- **原因の切り分け**: Join 画面の「Allow other devices on my network to connect」にチェックを入れて、
  もう一度繋ぎ直す。それで一覧に出るなら、「このパソコンだけに見せる」方式が環境に合っていません
  （ログの `Announcing LAN world … [インターフェイスの IP] — this computer only` と、
  その環境の情報を教えてください）。出ないなら、アナウンスの経路は無関係です。
  どちらの場合も、上の「直接アドレスを入力する」方法で入れます。

## 「その名前は既に使用されています」と出て入れない

ワールドに入ろうとすると、次のように表示されて弾かれる場合です。

> サーバーへの接続に失敗しました
> **その名前は既に使用されています**
> （英語版: *That name is already taken*）

**MineScale の不具合ではありません。** 接続はホストの Minecraft まで届いていて、ホストの
Minecraft が「同じプレイヤー名がすでに入っている」として断っています。

### 原因

- **ホストとジョインで、同じアカウント（同じプレイヤー名）を使っている。**
  ホスト本人がその名前でワールドに入っているため、同じ名前のジョイン側は入れません。
  2 台のパソコンを 1 人で試すときに、特に起こります。
- 同じ名前で入った直前の接続が、ホスト側にまだ残っている（数十秒で消えます）。

同じ Microsoft アカウントは、2 台から同時に入れません。

### 対処

- **ジョイン側を、ホストとは別のアカウント（別のプレイヤー名）にする。**
  ひとりで両方の役を試すときは、**別の Microsoft アカウント**（ログイン認証が通るもの）を
  ジョイン側に使ってください。**オフラインアカウントでは入れません**（次の項目を参照）。
- 直前に同じ名前で入っていた場合は、少し待ってからやり直す。

## 「無効なセッションです（ゲームとランチャーを再起動してください）」と出て入れない

ワールドに入ろうとすると、この表示で弾かれる場合です。**MineScale の不具合ではありません。**
接続はホストの Minecraft まで届いていて、**ジョイン側の Minecraft が、自分のログイン（セッション）を
無効と判断して、自分で切断**しています。

### 原因: 「入り方」で扱いが変わる

Minecraft は、ホストが認証を求めたとき、ジョイン側が自分のセッションを Mojang に確認します。
確認に失敗したときの扱いが、入り方で違います（Minecraft 1.21.11 と 26.3 の実コードで確認）。

| 入り方 | セッションが無効（オフラインアカウント、ログインの期限切れなど） |
|--------|------------------------------------------------------------|
| **マルチプレイ画面の「LAN ワールド」の項目から入る** | **入れる**（クライアントが認証の失敗を無視し、ホストの「LAN に公開」したワールドも通す） |
| **「サーバーを追加」「ダイレクト接続」でアドレスを入力して入る** | **入れない**（普通のサーバーとして扱われ、「無効なセッション」で切断される） |

つまり、**LAN の一覧に出ているときは、アカウントの種類を問わず入れます**。一覧に出ないので
アドレスを直接入力すると、有効なログインでないと弾かれます。

### 対処

- **ジョイン側を、ログインが有効なアカウントにする。** ランチャーのアカウントがオフラインになって
  いないか、ログインの期限が切れていないかを確認して、ゲームとランチャーを再起動してログインし直す。
- ホスト側がオフラインアカウントでも構いません（確認されるのは入ってくる側です）。アカウントが 1 つしか
  ない場合は、**ホストをオフラインアカウント、ジョインを有効なアカウント**にして試せます
  （ホストとは別のプレイヤー名にしてください。同じだと「その名前は既に使用されています」になります）。
- **LAN の一覧から入る**（出ない場合は、次の「LAN の一覧に出ない」を試す）。
- Paper などの専用サーバーは、既定（`online-mode=true`）では、一覧・直接を問わず有効なログインが必要です。

## LAN の一覧にワールドが出ない

直接アドレスの入力でも入れますが、上の「無効なセッション」の項のとおり、**アカウントによっては
直接入力だと入れません**。一覧に出すための確認事項です。

- **macOS: 「ローカルネットワーク」の許可**を確認する。システム設定 → プライバシーとセキュリティ →
  ローカルネットワーク で、**Minecraft を起動しているアプリ（Prism Launcher / Minecraft など）**と
  **MineScale** がオンになっているか。オフだと、マルチキャスト（LAN 検出）を受信・送信できません。
- Join 画面の **「Allow other devices on my network to connect」** にチェックを入れて繋ぎ直す。
  それで出るなら、「このパソコンだけに見せる」方式がその環境に合っていません
  （ログの `Announcing LAN world … [インターフェイスの IP] — this computer only` を教えてください）。
- VPN を切ってみる。マイクラを、MineScale の接続が済んでから開く。マルチプレイ画面を開き直す。

## 「切断されました」「タイムアウト」で途中から入れなくなる

繋がった直後は問題ないのに、しばらく操作しないでいて（たとえば一覧にワールドが出ないので探して
いる間に）、そのあと入ろうとすると失敗する場合です。ログに `Join stream error: timed out` と出ます。

- **v1.2.16 以前**は、直接接続（P2P）が無通信で約 30 秒たつと自動で切れていました。
  **v1.2.17 以降**は、定期的に信号を送って切れないようにしています。両方を更新してください。
- v1.2.17 以降でも直接接続が切れた場合は、画面の経路が **Relay** に切り替わり、新しい接続は
  Relay を使います（ログに `Direct connection lost` と出ます）。

## 直接接続も Relay も応答せず、タイムアウトする

ジョイン側で「QUIC handshake timed out」のあと Relay に切り替わっても、Minecraft が 30 秒ほど待って
失敗する場合です。**ホスト側のアプリが止まっている**可能性が高いです。

- ホストの画面を確認してください。**v1.2.18 以降**は、セッションがエラーで止まると、「Stop」ボタンと
  共有 URL が消えて、赤字で理由が表示されます（それ以前は、止まっていても動いて見えました）。
- ホストのアプリを**最新版（v1.2.18 以降）に更新**して、もう一度「Share World」から始めてください。
- 直らないときは、**ホスト側のログファイル**（下の「ログファイルの場所」）の `ERROR` / `WARN` の行を
  教えてください。

## ログファイルの場所

ログは**画面だけでなく、ファイルにもその場で追記**されています。アプリが落ちたり、画面を閉じたり、
画面のログが流れてしまっても残ります。ログはあなたのパソコンの中にだけ保存され、送信されません。

| OS | 場所 |
|----|------|
| macOS | `~/Library/Logs/MineScale/` |
| Windows | `%LOCALAPPDATA%\MineScale\logs\` |
| Linux | `~/.local/state/minescale/` |

GUI は `mc-share-gui.log`、CLI は `mc-share.log` です（5 MiB を超えると `.1` に退避します）。
問題を報告するときは、このファイルの該当部分を貼ってください（外部 IP や部屋 ID が含まれるので、
貼る前に内容を確認してください）。

## 同じネットワークの別のパソコンから繋げない / 見えない

既定では、**ジョイン側のパソコン自身だけ**がワールドを見られて、使えます。同じネットワークの
他の端末には表示されず、接続も拒否されます（共有 Wi-Fi などで他人に使われないようにするためです）。

同じ PC の中でもコンテナ・仮想マシン・WSL からマイクラを動かしている場合など、
別のアドレスから接続する構成では繋がらないことがあります。その場合は、
**意図して**次のどちらかで許可してください。

- CLI: `mc-share join <URL> --allow-lan`
- GUI: Join 画面の **「Allow other devices on my network to connect」** にチェック

許可すると、同じネットワークの他の端末にも一覧に表示され、接続もできるようになります。
信頼できるネットワークでだけ使ってください。

## UDP が塞がれた環境（会社・学校など）

直接接続（UDP）が使えない回線でも、自動で **Relay** に切り替わって繋がります。
画面に **「Relay (via server)」** と表示されている場合がそれです。Relay では
サーバーを経由する分だけ遅延が増え、MineScale による暗号化もありません。
詳しくは [SPEC.md](../SPEC.md) の「暗号化」を見てください。

## 友達が途中から入れない

共有 URL で新しく入れるのは、**作成から約 15 分間**です。過ぎたら、ホストがもう一度
「Share World」で新しい URL を発行してください（すでに入っている人は、そのまま遊べます）。
